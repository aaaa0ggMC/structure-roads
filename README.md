# 阡陌连路 / Structure Roads（1.12.2，开发初版）

这是独立实现，**不是阡陌交通 RoadWeaver 的官方移植**。面向本整合包的 Forge 1.12.2 / Cleanroom，源码保持 Java 8。0.1.0 已使用 Java 8 离线构建、重混淆，并通过共享池安装到两个实例；**尚未进游戏验证**，不能当作已经完成行为验收的成品。

**用户实测发现的阻塞（2026-10-30）：** 日志状态为 `routes=0`、`cachedEdges=0`。当前设计要求两个目标中心和整条路径都同时在已加载区块内，常规探索视距下通常无法连接村庄；持续生成区块时全局等待还会推迟工作。默认预览模式也不会落方块。**不能把关闭预览当成完整修复，当前版本尚不满足自动跨村庄生成道路的实际需求。** 后续需要跨区块持久化规划/延迟施工设计及实际行为验证。本次内容模组精简未修改道路配置或宣称修复此问题。

## 当前行为

- 不局限于村庄：目标和避让区域分开登记，可串联村庄、地表神庙、CQR 地表保护区，以及显式配置的 RC 结构。
- 默认半径 1536 格，每个目标选最近两个候选；半径外不连接。没有邻居就跳过，不扩大搜索，不调用 `/locate`，不为了找目标生成地形。
- 已加载且完成填充的区块中增量 A* 寻路：四格网格，但每条边中间的每一格以及三格宽路面都检查；拒绝悬崖、水面、树干、人工方块和已登记结构。
- 道路止于结构包围盒外围，**尚不识别实际大门，也不保证接通村庄内部小径**。
- 默认只规划预览。关闭预览后，服务端主线程分批铺三格宽碎石路，不开异步线程读写世界。每次落方块前重新验证。
- 不加载新区块；施工中遇到卸载暂停，遇到建筑或玩家改动停工。不自动回滚已铺道路。
- 只允许安装后发生自然填充的区块；旧区块默认不改。从安装之后观察到玩家放置/破坏的区块整块避让。**不能自动识别安装前的玩家建筑**。
- 结构、规划道路、施工游标、玩家编辑和可施工区块保存在每维度 WorldSavedData，重进存档可以续作；目前仅启用主世界。
- 扩展数/施工列数有每 tick 上限，寻路和施工各有软时间预算；单次第三方 API 调用不能被中断，**尚无实测性能数据**。

### 当前适配范围

| 来源 | 数据与行为 | 状态 |
| --- | --- | --- |
| 原版村庄、神庙 | `MapGenStructureData` 的 `BB`，地表目标及避让 | 已实现，待游戏验证 |
| Village Names 4.4.13 | 本地字节码确认继承 `MapGenVillage`，走同一村庄数据通道 | 已实现，待验证生成器配置差异 |
| Recurrent Complex Volts 2.0.1.2 | 公共结构数据 API / Post 事件读取实际包围盒；默认全部避让，配置精确结构 ID 后作为目标 | 已核对本地接口，待运行验证 |
| Chocolate Quest Repoured 2.8.0B | 公共保护区 API；已登记的地表区域作外围目标；生成中和地下区域不作目标 | 已核对本地接口，**不覆盖没有保护区域的地牢** |
| 冰火、Doomlike Dungeons、Additional Structures、Illagers+、AoA 等 | 不能假设存在统一结构登记 | **尚未自动适配**；可手工登记外围入口和避让盒 |
| Lost Cities 等整片城市地形 | 不能拿一个中心点当成普通独立建筑处理 | **尚未适配**，不建议在其世界类型中关闭预览 |

RC 生成树、装饰、小残骸也可能是“结构”，所以绝不默认把全部 RC 条目变成道路终点。`recurrentComplexTargets` 使用精确 ID 白名单，通过 `/sroads sites` 可以查看识别条目。

**安全边界：没有登记包围盒、保护区或适配器的模组结构无法保证自动绕开。** 方块白名单只是第二道保守检查，不是通用建筑识别器；泥土屋顶之类仍需结构数据。因此默认必须保持预览，在完成整合包适配和副本实测前不要在正式存档启用施工。

## 配置与调试

配置：`config/structureroads.cfg`，重启游戏生效。

- `previewOnly=true`：默认安全模式，不落方块。
- `connectionRadius=1536`、`nearestNeighbours=2`：有限路网，不全连接。
- `targetStructureData` / `protectionStructureData`：可增补其他采用原版 MapGenStructureData 格式的保存标识；不是 modid，也不是盲猜的结构名。
- `recurrentComplexTargets`：明确允许连接的 RC 模板 ID，默认空。
- `nodesPerTick=12`、`maxSearchNodes=12000`、`columnsPerTick=4`：负载控制，不是已验证的最优值。

管理员命令（权限 2）：

```text
/sroads status
/sroads sites [页码]
/sroads routes [页码]
/sroads show <路段索引>               # 最多 256 个临时粒子，需在附近查看
/sroads add <英文ID> <半径>           # 当前位置登记结构外围目标；内部同时保护
/sroads protect <英文ID> <x1> <y1> <z1> <x2> <y2> <z2>
/sroads allowchunk                   # 显式将当前位置单个旧区块加入允许施工集合
/sroads retry                        # 解除施工停工标志；不会绕过安全检查
```

手工目标/避让 ID 共用 `manual:` 命名空间，同 ID 可更新。`allowchunk` **不移除玩家编辑保护**，也不会自动授权周围区块。预览路线需要整个连接走廊都满足可施工条件；仅发现两个远处目标而未探索中间地形时，不会凭空生成路线。半径内邻居检查只针对当前已识别、且中心区块已加载的地表目标。

当前没有桥梁、隧道、人工削山填谷、自动删路、真实门口定位或跨维度道路。遇到阻塞宁可暂不连接；失败寻路至少冷却 1200 个有效 tick 再尝试。每目标的两个最近邻是候选上限，**不是节点总度数硬上限**。

## Xaero 世界地图联动

已实现针对本包 **Xaero World Map 1.47.0 + XaeroLib 1.7.3** 的可选客户端覆盖层源码（不是小地图联动），通过公共 `MapElementRenderHandler.add` / `ElementRenderer` 接口注册；没有改 Xaero jar，没有 coremod/mixin，也不往地图文件写东西。

- 绿色实线：已铺完的道路部分。
- 黄色虚线：规划中/尚未铺设的道路部分，预览模式也可显示。
- 红色短虚线：停工道路的未完成部分；已经铺完的部分仍为绿色。
- 小方块：道路两端，不是已定位的建筑大门，也不区分建筑类别。
- `/sroadmap toggle` 开关覆盖层；`/sroadmap planned` 开关未完成路段；`/sroadmap ends` 开关端点；`/sroadmap status` 查看同步/缓存状态。这些开关仅当前客户端运行期间有效；持久默认值在配置 `map` 分类。
- 仅主世界地表地图。洞穴图、其他维度、手工选中的其他地图不画当前世界的道路，避免串图。

### 同步和开销边界

客户端不读取集成服务器对象：专用 `SimpleNetworkWrapper` 请求/回复，服务器和客户端分别调度至各自主线程。没有安装本模组的服务器不发送请求；服务器仅回复主动请求的客户端。没有 Xaero 的客户端仍可正常加载道路模组，不请求地图数据；专用服务端不加载 Xaero/客户端渲染类。

服务器只下发两端所在区块都已发送给该玩家的道路边，不下发结构名字/包围盒/尚未下发区块的数据。**这里的可见性依据是 Minecraft 区块下发状态，不是 Xaero 的精确探索迷雾。** 客户端仅在当前世界会话内记住收到的路段；不持久化地图缓存，重连需要靠近相应区块重新获取，因此不会一打开地图就显示整个存档的所有道路。

同步通常每 40 个客户端 tick 一次，分页遍历视窗与玩家视距的交集；关闭地图时也低频记录附近已下发区块的道路。每包最多 2048 条一格道路边（最大 51219 字节），每请求检查至多 256 个区块单元与 2048 条边；Netty 入站和服务端主线程分别限流。不为同步调用生成器、加载区块或读取地图地形。施工状态在下一次覆盖到对应路段的分页同步时更新，不承诺即时刷新。

服务器每 tick 最多增量索引 256 条边，总索引最多 250000 边、每区块最多 4096 边。客户端缓存最多 16384 边，超限淘汰最久未更新的路段；状态显示 `cacheLimited=true`。缓存内连续同向/同状态的边合并，保持真实转弯和状态边界；绘制前按屏幕裁剪，最多 8192 个四边形，单批提交，尽量避免每条边一个绘制调用。**这些是代码上限，不是实测 FPS/TPS 保证。**

尚未实机验收：必须验证地图缩放/拖动/GUI 缩放、高分辨率、OptiFine 和 Actinium 下的对齐、透明混合与 GL 状态恢复；单人/多人同步、切世界/切维度/重连清缓存、服务端无 Xaero、客户端无 Xaero、无本模组服务器、限额截断和未下发区块不泄露数据。小地图和可点击的结构分类图标尚未实现。

## 构建

本机已有 `../morph-extension/gradlew`，可以共用包装器，不改动该项目：

```bash
JAVA_HOME=/usr/lib/jvm/java-8-openjdk ../morph-extension/gradlew -p "$PWD" --offline build
```

沿用 ForgeGradle 2.3 / Forge 2847 开发映射 `stable_39`，与本包 2860 运行时保持同一 1.12.2 API 目标。首次依赖缓存不全时 offline 会失败，不应未经确认转成联网下载。产物预期在 `build/libs/`，需要对 Forge 和 Cleanroom 分别验收，不能因 Java 8 源码语法通过就宣称双端兼容。

用户要求安装测试后，运行 jar 已放入 `_shared/mods/common/structure-roads-0.1.0.jar`，并执行 `scripts/sync-mods.sh` 同步到两个实例，确认三个路径为同一 inode。没有安装 sources jar、备份或旧版本。重启游戏后加载；首次运行自动生成配置，保持预览模式。实际铺路请仅在测试存档中将对应实例的 `config/structureroads.cfg` 中 `previewOnly` 改为 false 后重启；旧区块默认不施工，建议新测试存档。

## 必须补做的行为验收

使用独立测试存档/副本，不先动正式存档：

1. 两个近距离人工目标和一个半径外目标：只规划近邻；孤立目标无路。
2. 在候选走廊登记避让盒：路径绕开，窄到无法绕行时放弃；含道路边缘而不只是中心线。
3. 原版 + Village Names 村庄、RC 白名单模板、CQR 有保护地表地牢各测一组；生成中不能施工。
4. 旧区块/玩家放置方块/箱子/未知模组方块：不改；新区块等待填充稳定后才规划。
5. 卸载中间区块不强载；阻塞不反复每 tick 全量重算；重进存档继续且不重复规划同一连接。
6. 副本关闭预览：碎石路可走、不悬空，不穿建筑；重启后游标正确；地形改变后停工。
7. 分别在 Forge Java 8 与 Cleanroom Java 25 测专用服务端/集成服加载，记录 TPS、tick 开销与探索时的内存。

已做的检查：17 个 Java 文件的 Java 8 源码静态类型分析；资源 JSON 与部分 API 静态核对；随后使用本机真实 Java 8 执行离线 Gradle build，编译、reobfJar、sourceJar 均成功。构建时修复 Java 8 编译器在字段 lambda 与构造器提前 return 组合下的错误，并设置 Gradle 2 GB 堆解决源码包重映射内存不足。运行 jar 的 ZIP 完整性、版本元数据、全部 class major=52、重混淆 MC 引用、无内嵌 Xaero/MC/源码、无 coremod/mixin/CR 专用标记均已检查；安装后核对内容、硬链接、托管清单、无重复版本。Gradle test 为 NO-SOURCE，**没有行为测试或游戏启动证据**；构建成功不能证明渲染位置、网络行为或双运行时实际兼容性。
